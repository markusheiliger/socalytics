# Implementation Plan: Web UI Materialized Segment Management for Club Admins

**Branch**: `20261023-024906-web-ui-segment-management` | **Date**: 2026-10-23 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/20261023-024906-web-ui-segment-management/spec.md`

## Summary

Add a Club Admin-only segments area to the match page of the Web UI (`src/clients/web`) over the two existing
operations `listMaterializedSegments` and `purgeMaterializedSegments`
(`src/platform/SocAlytics.Platform.Api/Segments/MaterializedSegmentEndpoints.cs`). The area is a
`SegmentsSection` component in a new `features/segments` folder, mounted in `MatchPage` for Club Admins only, with an
application-owned `segmentAdapter` over the generated Kiota client, a `segments` translation namespace, a summary, the
list, an explicit refresh, and a purge confirmation dialog that follows the existing `ReconcileDialog` pattern (one
request, outcome or refusal shown, list re-read). The committed OpenAPI snapshot already carries both operations with
typed schemas ([research R1](research.md#r1-openapi-schemas)), so no platform operation, contract, or snapshot changes.
Evidence: Vitest unit tests, Playwright `simulated` tests with a scripted segment API in the simulated API support, and
one chained Playwright `platform` project (`platform-segments`) that drives real segment states against the AppHost
([research R4](research.md#r4-real-segment-states-in-the-platform-project)).

## Technical Context

**Language/Version**: TypeScript (strict) with React 19 for the Web UI (Node.js 24); no C# production change (one
e2e-mode configuration value in the AppHost, see R4)

**Primary Dependencies**: Existing Web UI stack only: React Router 7, TanStack Query 5, MUI 7, i18next, and the Kiota
1.36.0 generated client (`src/clients/web/src/generated/platform-api`, git-ignored and regenerated by the build); no new
packages

**Storage**: N/A (segment data stays in the TanStack Query cache in memory; nothing in browser storage, the offline
journal, or service-worker caches)

**Testing**: Vitest with Testing Library (`npm test`); Playwright 1.63.0 `simulated` and `platform` projects with
axe-core (`npm run test:e2e`)

**Target Platform**: Evergreen browsers and the installed PWA, served on one origin with the API by the AppHost

**Project Type**: Web application (SPA client of the platform API)

**Performance Goals**: One list read per area open or refresh, one purge request plus one list read per confirmed purge;
no polling

**Constraints**: Online only (FR-017); Club Admin only with the platform authoritative (FR-001, FR-002); no new or
changed platform operation, contract, or OpenAPI document (FR-018); memory-only data (FR-008); WCAG 2.2 AA (FR-015)

**Scale/Scope**: 1 section, 1 dialog, 1 adapter, 1 translation namespace, 1 browser-test project; the list is not paged
