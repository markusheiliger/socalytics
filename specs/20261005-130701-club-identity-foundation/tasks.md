**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/openapi.yaml](contracts/openapi.yaml), [quickstart.md](quickstart.md). **Tests**: Required. The spec's success criteria (SC-003 to SC-008) and constitution principle IV demand automated evidence, and [quickstart.md](quickstart.md) § 2 lists the scenarios A1 to A57. Every test is written in the same task as the code it verifies (or in the task immediately after it) and must pass when that task ends. After every task, `dotnet restore`, `dotnet build` (warnings are errors), and `dotnet test` of `src/platform/SocAlytics.Platform.slnx` must be green.

**Organization**: Tasks are grouped by user story to enable independent implementation and testing of each story.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks); informational only, because tasks run in file order
- **[Story]**: Which user story this task belongs to (US1 to US6)
- Every task names its exact file paths, requirement IDs, and design sections

## Path Conventions

- Production code: `src/platform/SocAlytics.Platform.{Domain,Application,Infrastructure,Api,AppHost}/`, with functional-area folders and namespaces `Club` and `IdentityAccess` (no new projects).
- Tests: `src/platform/Tests/SocAlytics.Platform.Integration.Tests/{Abstractions,Club,IdentityAccess}/` (behavior and pure rules; `Abstractions/` holds the shared Application abstraction tests), `src/platform/Tests/SocAlytics.Platform.Architecture.Tests/`, and `src/platform/Tests/SocAlytics.Platform.Host.Tests/`.
- Migrations: `src/platform/SocAlytics.Platform.Infrastructure/Persistence/Migrations/NNNN_<area>_<description>.sql`, numbered as the next free four-digit sequence numbers at implementation time.
- Application command handlers follow one convention: a `<Name>Command` (or `<Name>Query`) record plus a public sealed `<Name>Handler` class with `Task<OperationResult<T>> HandleAsync(<Name>Command, CancellationToken)`, registered as scoped in `AddApplication()`. Infrastructure implementations stay `internal` and are registered only by `AddInfrastructure()`.
