# Tasks: Durable Analysis Workflow

**Input**: Design documents from `specs/20261005-130703-durable-analysis-workflow/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/README.md](contracts/README.md), [contracts/openapi.yaml](contracts/openapi.yaml), [contracts/schemas/](contracts/schemas/), [quickstart.md](quickstart.md)

**Tests**: Required. The spec demands executable evidence (Assumptions → Evidence; SC-001 to SC-010) and the constitution requires focused tests in `src/platform/Tests`. Every test is written in the same task as the code it verifies, or in the task immediately after it for already-implemented code, so restore, build (warnings are errors), and the full solution test suite stay green after every task.

**Organization**: Tasks are grouped by user story and executed strictly in file order, one task per run. Every task is self-contained: it names exact paths, the types, members, and SQL objects to create, the requirement IDs it satisfies, and the design section it follows.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks); informational only, runs are sequential
- **[Story]**: Which user story this task belongs to (US1 to US5)
- Include exact file paths in descriptions
