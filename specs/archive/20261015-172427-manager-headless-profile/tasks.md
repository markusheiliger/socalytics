# Tasks: Analyst Manager Headless Server Profile

**Input**: Design documents from `specs/archive/20261015-172427-manager-headless-profile/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/headless-manager.md](contracts/headless-manager.md), [quickstart.md](quickstart.md)

**Tests**: Required by the constitution. Every task adds the tests for the code it creates in the same task, so the Manager solution, the platform solution, and the Web UI build and their test suites stay green after each task.

**Organization**: Tasks are grouped by user story. Merged before this feature starts (do not re-create): Analyst Manager Registration (`RegistrationCoordinator`, `IDeviceKeyProvider`, `DeviceKeyProviderSelector`, `Pkcs11KeyProvider`, `SingleInstanceGuard`, `LocalControlServer`, `LocalControlPaths`, `IAutostartRegistrar`, `XdgAutostartRegistrar`, `AutostartEntryFormats`, `src/analysts/manager/contracts/local-control.schema.json`, the platform's `StartPairing`, `DeviceMetadata`, `RegistryOptions`, `RegistryAuditEvents`, `AnalystManagerPairingEndpoints`), Analyst Manager Work Execution (`PreflightRunner`, `IContainerRuntimeAdapter`, `RuntimeProbe`, `SimulatedRuntimeAdapter`, `SimulatedAnalystOptions`, `OperatingOptions.DrainTimeout`), Analyst Manager Status Report and Fleet Read API (`ReadRegistrations`, `AnalystManagerRegistrationEndpoints`), and Web UI Analyst Manager Fleet and Registration Approval (`PairingPage.tsx`, `MyRequestPage.tsx`, `RegistrationPage.tsx`, `FleetPage.tsx`). No migration is needed. The Docker Desktop Runtime Adapter spec, in progress at planning time, also changes `IContainerRuntimeAdapter.cs`, `RuntimeProbe`, and `PreflightRunner.cs`; when it has merged first, its adapter reports `DaemonAccess = null`.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks); consecutive `[P]` tasks under one heading run in parallel, each from the same commit
- **[Story]**: Which user story this task belongs to (US1–US4)
- Every task names its exact file paths
