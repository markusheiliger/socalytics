## Phase 3: User Story 1 - Evaluate a capability on a labelled corpus and get a report (Priority: P1) 🎯 MVP

**Goal**: One command evaluates a capability reference on a corpus and writes a per-profile, per-label-kind report.

**Independent Test**: Evaluate a scripted capability (subprocess mode) on the builder corpus; the report lists one
result per clip, metrics for both profiles separately, and the planted discrepancies against the labels they violate.

### US1 modules

- [x] T017 [P] [US1] Implement `HARNESS/src/analyst_evaluation_harness/matching.py`: a label-kind registry
  `{kind: matching rule}` with the first rule `fact-position` (same kind; `startMs` equal to `positionMs` within the
  label kind's `matchToleranceMs`, or inside `[rangeStartMs - tolerance, rangeEndMs + tolerance]`; payload compared by
  deep equality of the labelled keys only when the label carries `payload`), one-to-one greedy pairing by increasing
  distance (`0` when the fact lies inside the unwidened range, otherwise the distance to the nearest range end) with
  ties by label then fact order, a pair with an unmet payload expectation as a miss plus a false
  positive, misses with reason `no-fact`, `payload-mismatch`, or `clip-failed`, and facts of kinds without labels as
  `unlabelled` (FR-005, FR-012, FR-018; data-model "Pairing result")

  `precisionUndefined`, `recallUndefined`, or `f1Undefined` reason when the denominator is 0, a failed clip

- [x] T019 [P] [US1] Implement `HARNESS/src/analyst_evaluation_harness/runners.py` with the subprocess runner (command

  manifest (`matchStartMs` plus the duration) and writes one fact per second for every label kind declared in the

## Dependencies & Execution Order

- Phase 1 (T001, which also generates the lock and carries the first collectable test, → T004 (project layout test), with T002 and T003 in parallel after T001) precedes everything.
- Phase 2 blocks all user stories; within it the modules (T005 to T010) precede the tests (T011 to T016).
- Consecutive `[P]` tasks under one heading run in parallel: the Phase 2 modules (T005 to T010) and tests (T011 to
  T016), the US1 modules (T017 to T020) and tests (T024 to T029), the US2 comparator and gates (T030, T031) and tests
  (T035 to T037), the US3 modules (T038, T039) and tests (T042 to T044), the US4 tests (T046, T047), and the
  documentation (T049 to T053).
- US1 (Phase 3) is the MVP; US2 builds on its runners, `evaluate.py`, `report.py`, and `__main__.py`; US3 builds on the
  US2 `gates.py`, `evaluate.py`, and `report.py`. The story order is therefore sequential: US1 → US2 → US3.
- US4 (T045) needs only Phase 2 and the CLI of US1 for validation, but its end-to-end test T047 needs US1 to US3 for
  comparators and determinism; US5 needs US1.
- Polish documentation (T049 to T053) needs the implemented behavior; T054 runs last.
