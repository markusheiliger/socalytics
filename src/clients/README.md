# Clients

## Purpose

This area owns SocAlytics user-facing client applications.

## Ownership

The boundary is the React Web UI, a Progressive Web App on a single origin. It serves every workflow, including coach workflows and the later offline mode for coaches; there is no second client application. The online-only Web UI foundation is implemented in [`web/`](web/) as development evidence.

## Exclusions

Platform API implementation, server runtime composition, agent runtimes, and Analyst execution software do not belong here. No service worker, offline mode, container image, or deployment configuration exists yet.

## Current Status

`web/` is a React, TypeScript, and Vite application with React Router, TanStack Query, MUI, and i18next. Its API client is generated by Kiota into the ignored `web/src/generated/` folder from the committed OpenAPI snapshot `src/platform/SocAlytics.Platform.Api/openapi/v1.json` and is used only behind local adapters. It includes the Analyst Manager views: the pairing page and a Registrar's own requests, and for Club Admins the fleet with its filters, the approval and rejection decision, and revocation by typing the host label, with the pending count in the navigation. The claimed application profile is not shown until Managers report it. This is development evidence, not production readiness.

## Commands

Prerequisites: Node.js 24, the Kiota 1.36.0 CLI on `PATH` (`dotnet tool install --global Microsoft.OpenApi.Kiota --version 1.36.0`), and the Playwright Chromium browser (`npx playwright@1.63.0 install chromium`). Docker is needed for the `platform` browser tests and the AppHost. Run from `src/clients/web/`:

```powershell
npm ci
npm run build      # Kiota generation, type checking, production build with Subresource Integrity
npm test           # Vitest unit tests
npm run test:e2e   # Playwright, both projects
```

Browser-test projects:

- `simulated` runs against `vite preview` with a simulated API and needs no Docker (`npm run test:e2e -- --project simulated`).
- `platform` runs one spec after another through chained projects against the real platform, which the Playwright web server starts through the AppHost in e2e mode (`npm run test:e2e -- --project platform`). The `manager-fleet` spec there drives a scripted Manager (`tests/e2e/support/scriptedManager.ts`) through pairing, activation, status reports, and revocation.

The AppHost (`dotnet run --project src/platform/SocAlytics.Platform.AppHost`) also starts the Web UI on one origin with the API. After API changes, refresh the OpenAPI snapshot as described in the root [README](../../README.md#web-ui).
